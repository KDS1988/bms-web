# BMS · Назначения (веб-версия)

Замена Google-таблицы: доска мероприятий, назначение людей в BMS (со ставками), график персонала, поиск назначений без ставок.

```
Браузер (GitHub Pages, папка web/)  ──►  Cloudflare Worker (worker/)  ──►  BMS API
        только рисует                     токены BMS, права, логика
```
Токены BMS живут только в Worker (Durable Object) и никогда не попадают в браузер.

## Попробовать без деплоя
Откройте `docs/index.html?demo=1` (через любой статический сервер, напр. `python3 -m http.server` в папке `web`) — тестовые данные, в BMS ничего не уходит.

## Деплой (один раз, ~20 минут)

### 1. Google Client ID (вход сотрудников)
console.cloud.google.com → APIs & Services → Credentials → Create OAuth client ID → *Web application*.
Authorized JavaScript origins: `https://ВАШ-ЛОГИН.github.io` (и `http://localhost:8765` для проверок).
Скопируйте Client ID.

### 2. Worker
```
cd worker
npm install
# в wrangler.toml заполните ALLOWED_ORIGIN, GOOGLE_CLIENT_ID, ADMIN_EMAILS / EDITOR_EMAILS / VIEWER_EMAILS
npx wrangler secret put SESSION_SECRET      # любая длинная случайная строка (32+ символов)
npx wrangler deploy                         # выведет адрес https://bms-web.<поддомен>.workers.dev
```
Роли: **viewer** — смотрит; **editor** — назначает и доначисляет ставки; **admin** — ещё входит в BMS.
Можно писать `@vsporte.ru`, чтобы пустить весь домен. Убрали email из списка — доступ пропадает сразу.

### 3. Страница
В `docs/config.js` впишите адрес Worker и Client ID. Выложите папку `docs/` на GitHub Pages
(репозиторий → Settings → Pages → Deploy from branch → папка `/web` либо перенесите файлы в корень/`docs`).

### 4. Вход сервиса в BMS
Откройте сайт под админом → вкладка **«BMS-вход»** → телефон → «Получить код» → код из SMS → «Войти».
Сессия обновляется автоматически (refresh-токен ротируется внутри Durable Object).
Если BMS разлогинит сервис — на сайте появится плашка, повторите вход.
Лучше использовать отдельную служебную учётку BMS: все назначения будут уходить от её имени (кто нажал — пишется в логи Worker: `wrangler tail`).

## Что где
- **Доска** — по дням, колонки ВР/Прод/Реж/Повт/Титры/Звук/Инж/Опер; цвета: принял / ждёт / отказ / подрядчик; ⚠ — нет ставки; «＋» — назначить (список: свободные → занятые → «не может»). Для ВР автоматически ставятся удалённая логистика и допуслуги БК/рек.
- **График** — сотрудники × даты (свободен / занят / выходной), фильтр по амплуа.
- **Ставки** — назначения без ставки и кнопка «Доначислить все».
- Фильтры доски (услуги «Прямая трансляция»/«Студия», без ХЛТР/ФХМ) — `worker/src/board.js`.

## Тесты
`cd worker && npm test` — 11 тестов (доска, двухшаговое назначение, дубликаты, 401→refresh, ставки, график, JWT/роли).

## Что не проверено на живом BMS
Формат ответа `admin/employee/schedule` и `admin/catalog/line/list` взят из прежнего скрипта; если график или список кандидатов придут пустыми — пришлите ответ `wrangler tail`, поправлю разбор в `worker/src/index.js`/`staff.js`.

## Старое
GitHub Actions-опрос и Telegram-уведомления (poll_bms.py) этот сервис не заменяет; их можно оставить как есть.
